# Clavero 1.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import from other password and 2FA apps by merging into the vault, add three tools (Repartir un secreto, Laboratorio de hashes, Laboratorio clásico), add «Comprobar una copia», run every `BiometricVault` operation in one queue and, if it fits, move to AGP 9.

**Architecture:**
- Everything outside `ui/` and `android/` is pure Kotlin, so `jvm-check` compiles and tests it too.
- **Importing:** each format has its own reader, which produces one common model (`ImportRead`). A pure merge plan (`MergePlan`) turns that model into the preview. The vault is written once, through `VaultStore.applyImport`, and only after the pre-import copy.
- **The new tools** are pure functions with a thin Compose screen each. Their state lives in a ViewModel.

**Tech Stack:** Kotlin 2.4, Compose, AGP 8.13 (9.x in Task 11), Bouncy Castle 1.86, `javax.crypto`, kotlinx-serialization and coroutines, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-03-clavero-1.4.0-design.md`, approved by the owner on 3-11-2026. Read it together with this plan: the plan does not repeat the spec's reasons.

## Global Constraints

  - Clavero's formats are read forever and never change: `SG1:`, `.sgenc`, `seguridad-vault` v2/v3, `seguridad-backup` v1/v2, `SGK1:`, `SGM1:`, `SGS1:`.
  - Crypto comes only from `javax.crypto` and Bouncy Castle.
  - Only free dependencies with permissive licences (Apache-2.0, MIT, BSD, ISC; CC BY for data).
  - Network goes only to `api.pwnedpasswords.com`.
  - No log ever contains data.
  - `FLAG_SECURE` everywhere.
  - The UI is in Spanish.
  - Every minor finding is fixed; none is deferred.

## Review Focus

1. **A real export with a header or field the hand-made fixtures did not have:** an extra Chrome column, Firefox column order, a Bitwarden item with `login: null`. The import must still work, with the unknown column ignored and the item listed under «no entran», never crash. → Tests in Task 6 and Task 7: `unknownColumnsAreIgnored`, `itemWithNullLoginGoesToSkipped`.
2. **The vault changes between preview and confirm:** an auto-lock, an edit in another window, a sync. The import must not apply a plan built on old entries. → Task 8: `applyRefusesAStalePlan`.
3. **A huge or deeply nested JSON:** it must be refused fast, without a stack overflow or an OOM. → Task 7: `deepJsonIsRefused` (depth > 64) and `itemCountOverLimitIsRefused`.
4. **A pre-import copy into a provider that cannot rename** (`BackupFile.canRename == false`, as some cloud folders): the copy must still be complete under its final name, or the import must not run. → Task 8: `copyBeforeImportWithoutRenameWritesFinalName`.
5. **Two imports of the same file in a row:** with «saltar», the second must add nothing. Duplicates must be found again against what the first import added. → Task 8: `secondImportOfSameFileAddsNothing`.
